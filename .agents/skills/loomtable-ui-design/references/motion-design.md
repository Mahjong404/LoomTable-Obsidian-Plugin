# Motion Design — LoomTable Agent 操作规程

涉及新增/调整动效、审查过渡、拖动/滚动不自然或掉帧时加载。适用于 Obsidian 中安静、精确、高密度的数据工作；已有批准设计直接进入对应实施切片。

本文件规定 Agent 的判断与验证流程。视觉与参数读 [Design System](../../../../docs/ui/design-system.md)，行为、键盘、焦点与降级读 [HIG](../../../../docs/ui/interaction-hig.md)，异步编辑所有权读 [Editor Lifecycle](../../../../docs/architecture/field-editor-lifecycle.md)，授权范围读 [Wave 1.5](../../../../docs/wave1.5/README.md)。这些来源优先，不在 Skill 复制数值表或建立另一套 Motion Token。

## 1. 先判断动效是否有用

为当前元素写清：触发事件、实际状态变化、用户看到它的频率，以及动效解释什么。目标只能是输入反馈、状态可辨识、空间连续性或必要的变化提示；没有用途就保留静态反馈。

| 场景                                | 判断方向                                                               |
| ----------------------------------- | ---------------------------------------------------------------------- |
| Grid 导航、键入、连续选择、反复开关 | 输入、焦点和数据立即响应；高频反馈优先直接落位或最少过渡               |
| 已批准的固定状态切换                | 按既有合同做短而克制的过渡，目标值立即更新，避免弹跳和过冲             |
| Pointer 拖动或原生滚动              | 保持输入与可见位置连续对应；释放后的过渡/Snap 按组件合同               |
| Popover/Sheet 打开、关闭            | 先保证定位、命中与焦点生命周期；如需过渡，路径应解释触发点与浮层的关系 |
| 保存、失败、冲突、Loading           | 状态来自真实业务结果；静态文本/图标始终可读，不以播放完毕宣布成功      |
| Obsidian 原生 Menu/Notice/Modal     | 保留宿主反馈，避免叠加第二层动画                                       |

频率决定克制程度，不以固定次数或“键盘触发”一刀切推翻已批准合同。键盘操作不等待动画；数据阅读和工作区恢复不增加入场编排。

完成条件：能说明用途，或明确选择零新增动效；不顺带搜索整个产品的动画机会。

## 2. 读取合同并限定参数

先查组件现有 HIG/DS、实际源码与测试，列出动画属性、起止状态、时长/缓动来源、输入方式、降级路径和取消条件。Clock/Wheel/AMPM 直接引用 HIG 的 Future TimePicker 合同；视觉批准不解锁 Time/DateTime 持久化。

无具体数值合同的普通反馈，选择满足用途的最短、最小变化；进入和状态反馈优先考虑快速响应、平稳停止的缓动，不默认套强烈曲线或弹簧。固定时长适合可预测的切换；精确选择控件不叠加额外惯性、回弹或过冲。需要形成长期组件合同的新决策写入对应正式规范一次，普通实现选择在切片 review 中说明。

完成条件：参数来自现有合同，或明确记录本切片的选择与验证；不照搬外部时长、弹簧参数或通用视觉默认值。

## 3. 选择最小实现，保护状态所有权

- 优先复用宿主与现有组件。有限状态切换通常用作用域内 CSS transition，显式列出属性；仅在确需程序控制且宿主支持时考虑原生 WAAPI。连续几何输入按已有合同使用 Pointer Events/rAF，滚动优先保持 native 行为；不引入动画库或新框架。
- 优先小范围的 transform/opacity；合同需要的文字颜色变化保持可读。不为动效改变 Grid 行高、编辑器尺寸、布局测量或增加冗余交互 DOM。光标、焦点环、文字和命中区域在过渡中保持稳定；不能简单用 scale 替换所有尺寸变化。
- 快速切换从当前可见位置重定向，新输入取消旧过渡/Snap；检查版本或上下文，旧 completion 不反写新 draft。不要把固定 keyframes 重播作为连续输入或快速切换的默认方案。
- 逻辑目标、可见插值、提交生命周期分别识别所有者。保留现有 Controller/Mutation Queue/commit owner；transitionend、animationend、WAAPI finished 或 rAF 完成均不得承担业务提交。
- 退出过渡不得拖延 Esc/Tab/外点关闭或抢回焦点；残留绘制层不接受交互。销毁、上下文切换和取消时释放本次 timer/rAF/listener/capture/observer；已发 Mutation 仍按现有所有权处理。
- 性能诊断先找实际 Layout/Paint/长任务与节点范围，避免逐帧改大型祖先上的继承变量或重绘整个 Grid。CSS/WAAPI 与 transform 不保证始终由 GPU 执行；will-change 只在测量支持时局部使用并释放，不给全部单元格预分配图层。

完成条件：实现只覆盖当前消费者和真实状态，能解释快速中断与销毁路径，不形成独立保存系统或通用动画引擎。

## 4. 降级随功能交付

- CSS 与 JS 驱动都处理 prefers-reduced-motion，支持偏好变化；优先复用现有 a11y 基础。位置/旋转/Snap 按组件合同直接落位，保留连续输入、可读状态和完整业务语义；不能只在 CSS 中缩短时长而遗留 JS 循环。
- Hover 专属视觉反馈按 hover/pointer 能力启用；键盘和触屏仍有即时反馈，不依赖 hover 或动画完成才能使用。
- 不以透明度藏住正在阅读/编辑的值、焦点或错误信息。状态与 ARIA 可独立理解；动画装饰层不得成为重复的可访问控件。

完成条件：默认与 reduced motion 到达相同逻辑结果，取消/确认语义不变，偏好变化不会留下旧动画回调。

## 5. 按证据验收

| 层次                 | 必须区分的证据                                                                       |
| -------------------- | ------------------------------------------------------------------------------------ |
| 源码/Unit/DOM        | 参数来源、状态转换、中断、一次提交、旧回调隔离、资源释放；不能证明视觉流畅           |
| 真实生产组件 Gallery | 明暗主题、窄容器、长文本、命中与裁剪、快速反复操作、reduced motion；避免另写展示副本 |
| Obsidian Desktop     | 键盘/Pointer/Wheel、焦点、关闭、上下文切换、运行中偏好变化、主线程负载和宿主兼容     |
| 实际移动设备         | Touch、滚动手势、键盘遮挡、WebView、真实性能；桌面模拟不等于移动端通过               |

验收先用正常速度操作，再用慢放/逐帧定位跳变、遮挡和错误起点。检查快速反向、连续输入、Esc/外点/Tab、模式/记录切换与销毁；性能问题用录制验证，按实际设备刷新率评估帧预算，桌面 CPU 限速不能证明移动 GPU/内存表现。

报告每项“已验证/未验证”、环境与证据；未运行宿主就写待 Runtime QA。Figma 静态状态或可播放动画均不替代交互验收，也不作为实施前置。

## 不引入的内容

- 营销式滚动叙事、视差、磁吸光标、3D 倾斜、粒子/庆祝、文字拆分入场、批量 stagger、无业务目的的循环与背景动效。
- 对所有按钮统一缩放、对数据区弹簧回弹、用 blur 掩盖错误状态/中断、为效果复制可访问控件。
- 全局 reduced-motion 覆盖、外部默认 Token/视觉语言、动画库安装、重新生成 Design System、自动多 Agent 探索或全站重设计。
- 为已批准 Wave 1.5 新建 Figma Motion 验证、工具扩展或反复审批流程。Future/API-gated 能力继续等待合同；运行时动效随获授权组件实现。
